# AGENTS.md

## What this is

An implementation of the Kubernetes custom metrics and external metrics APIs backed by Elasticsearch: it exposes metrics stored in Elasticsearch (collected by Metricbeat/Agent) so the Horizontal Pod Autoscaler can scale workloads on them. Ships as a single Go binary (`main.go`) deployed via the Helm chart in `helm/`; Buildkite promotes builds from `main` into serverless-gitops.

## Owner

Team: ECP Services (`group:ecp-services` in catalog-info.yaml) · Slack: #ecp-serverless-services

## Setup & everyday commands

```bash
make all            # build the adapter binary + license-header check
make test           # unit tests with coverage (go test ./pkg/...)
make validate-helm  # helm lint + helm template on helm/
make go-run         # run the adapter locally against ~/.kube/config (insecure, port 6443)
make tidy           # go mod tidy
make docker-build   # container image (regenerates openapi code + NOTICE.txt first)
```

- Go version: see `go.mod` (currently 1.26.x). Heads-up: `make test` first runs `go env -w GOTOOLCHAIN=go1.25.4+auto` (temp workaround for golang/go#75031) — it mutates your global Go env.
- No Makefile lint target yet. `.golangci.yml` at the root is a baseline golangci-lint config (default linter set), not wired into CI.
- Local runtime config goes in `config/config.yml` (gitignored); start from `config/config.example.yml`.

## Repo layout

- `main.go` — adapter entrypoint (custom-metrics apiserver)
- `pkg/` — implementation: `client/` (Elasticsearch + custom metrics API clients), `provider/`, `registry/`, `scheduler/`, `config/`, `monitoring/`, `tracing/`, `profiling/`
- `generated/openapi/` — generated OpenAPI code (never edit by hand)
- `helm/` — Helm chart; `helm/README.md` covers configuration and deployment
- `hack/` — license-header check script + NOTICE generation assets
- `.buildkite/` — CI of record

## CI

- Buildkite is the CI of record (`.buildkite/pipeline.yml`): runs `make test`, `make all`, `make validate-helm`, publishes the Helm chart and container images, and on `main` triggers gpctl promotion into serverless-gitops. Failures on `main` notify #ecp-services-notifications.
- `.buildkite/pipeline.elasticsearch-k8s-metrics-adapter-tests.yaml` (+ per-env qa/staging/production variants) is a separate, manually-triggered environment test pipeline.
- GitHub Actions in `.github/workflows/` run auxiliary automation only: Renovate auto-approval and the AI agent workflows (`trigger-*.yml`).

## Never modify

- `generated/openapi/zz_generated.openapi.go` — regenerated by the Makefile openapi-gen target when `go.mod`/`go.sum` change
- `NOTICE.txt` — regenerated by `make generate-notice-file`
- `go.sum` by hand — managed by Go tooling

## Conventions

- Every source file needs the Elastic license header; `make check-license-header` (part of `make all`) fails the build otherwise. Boilerplate lives in `hack/boilerplate.go.txt`.
- After dependency changes: `make tidy`, and regenerate `NOTICE.txt` with `make generate-notice-file` (docker builds do this automatically).
- Renovate manages dependency PRs; the existing `auto-approve-renovate-prs.yaml` workflow auto-approves labeled ones (see `.github/workflows/README.md`).
- The adapter is `lifecycle: experimental` (catalog-info.yaml) — README warns it is not yet fully supported in production.
